# memory-engine — движок памяти и непрерывности

Код заморожен 05.08.2026 на время наблюдения (7 дней или 100 реальных поисков);
любая функциональная правка обнуляет отсчёт. Выложено для разбора.

Данных здесь нет — только код. Содержимое памяти лежит в приватных репозиториях.

| Файл | Что делает |
|---|---|
| `memoryctl.py` | Единственный вход: `search`, `doctor`, `recent`. Имена внутренних модулей в документации не пишутся — расхождение карты с кодом однажды стоило восьми минут раскопок. |
| `health.py` | Честная деградация: `ok / partial / failed`, коды 0/2/3, громкий баннер. 🔴 «Ничего не найдено» — правда ТОЛЬКО когда баннера нет. |
| `catalog.py` | Индексирование транскриптов хвостом, очередь изменённых сессий, переживающая смерть процесса. |
| `artifacts.py` | Индекс продуктов работы: какие папки и файлы появились и когда. Свалки на сотни тысяч файлов идут одной записью. |
| `claims.py` | Срок годности утверждений по классу: «действует сейчас» протухает, «решение» — нет. |
| `find.py`, `fts.py`, `vectors.py` | Поиск: смысловой и точный, с честным статусом обоих. |
| `worker.py` | Фоновая сборка. Владение локом атомарное, живого владельца не вытесняет. |
| `redact.py` | Вычистка секретов до записи в индекс. |

## Правила, каждое куплено ошибкой

- пустая выдача правдива только при `status=ok`, иначе это поломка, а не отсутствие;
- отставание индекса считается сверкой файлов, а не максимальной отметкой времени
  (она врёт в обе стороны);
- отпечаток начала файла берётся по ПРЕЖНЕМУ размеру: у короткого файла любое
  дописывание меняет отпечаток целиком;
- владелец лока — не только номер процесса; живого владельца не вытесняем.
