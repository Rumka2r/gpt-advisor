# agent-control — координатор и сборщик ресурсов агентов

Код для разбора. Разворачивается на сервере в `/opt/agent-control/`.

| Файл | Что это |
|---|---|
| `cp.py` | Control Plane: задачи, присутствие, аренды с поколениями, журнал событий, удержания. SQLite в WAL за демоном; Unix-сокет с определением личности по UID, TCP по ключу для Моста. |
| `ctl.py` | Клиент. `run` берёт ресурсы, держит сердцебиение и **убивает всю группу процессов при потере права**. Такт 20 с обычный, 3 с для необратимых операций. |
| `gc.py` | Сборщик ресурсов. Машина состояний `ACTIVE → EXPIRED → QUARANTINING → QUARANTINED → PURGEABLE → DELETED`, фиксация каждого перехода до действий на диске. |
| `test_cp.py` | Проверки координатора: 29 из 29. |
| `test_gc.py` | Регрессии сборщика: 47 из 47, по одной на каждый найденный дефект. |

## Правила, каждое куплено ошибкой

- разрушительное действие — только под атомарным захватом в координаторе;
- координатор недоступен → не удаляем ничего (молчание ≠ «владельца нет»);
- корень не прочитан → ничего под ним не считаем исчезнувшим, `--apply` запрещён;
- любая проверка, которую не удалось выполнить, значит «не удалять»;
- режим показа не переносит и не удаляет ничего, даже в архиве;
- минимальная выдержка не обнуляется даже при переполненном диске;
- спасательные ссылки создаются только в архиве под root, куда исполнитель писать не может.

`--apply` выключен до окончания проверки кода.
